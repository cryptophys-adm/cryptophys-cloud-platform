# Antigravity worker guide (code tasks TP-006 to TP-009)

You are the **code worker**. The orchestrator and validator is the Claude cloud session; it reviews your PRs, merges them and runs every deployment. The owner is the repository owner.

Read this file, then `taskplane-tasks/CONTEXT.md` (hard rules), then the task's `PROMPT.md`. Do **one task per PR**, in this order: **TP-006 → TP-007 → TP-008 → TP-009**. Each task builds on the previous one being merged into `main`.

## Architecture you are extending (read these first)

- `architecture/adr/0007-ai-worker-os.md`: the kernel, syscalls, autonomy tiers, the kill switch and MCP.
- `architecture/AI-ENGINE-REQUIREMENT.md`: one AI engine per Worker, with budgets, validators and typed outcomes.
- `workers/control-plane-shared/src/capabilities.ts`: the capability catalog and the syscall checks.
- `workers/ai-kernel/src/`: `syscall.ts` (the gate), `supervisor.ts` (an agent cycle; copy its shape), `kernel.ts`, `mcp.ts`, `index.ts`, `worker.ts`.
- `workers/control-plane-shared/test/ai-kernel.test.ts`: how agents are tested in Node with real migrations, fake AI and fake bindings. Copy its patterns.

## Non-negotiable rules for code tasks

1. **Tiers.**
   - No new capability may be tier 3. Trading, orders, exchange accounts, wallets and fund movements are prohibited (`PROHIBITED_CAPABILITY`).
   - An agent's `tier_max` is at most 1 unless the task says otherwise. Every tier ≥ 1 action goes through `syscall()`, and its target re-verifies the decision with `verifySyscallDecision`.
2. **AI never decides.**
   - Deterministic code decides *whether* to act. AI only drafts text, and its output is validated by a strict `validate()`.
   - When AI is unavailable or returns invalid output, a deterministic template is used.
   - AI may never change a number, a decision or an action that came from data.
3. **Advisory only.** Every report about markets carries the deterministic disclaimer `advisory only; not an order`. Never write anything that executes, orders or signs.
4. **Migrations.**
   - Add a new numbered file only. Never edit a merged migration.
   - Update `REQUIRED_MIGRATION` in `control-plane-shared/src/readiness.ts` to your new file.
   - Make `python3 workers/control-plane-migrations/test_migrations.py` pass.
5. **Files you may touch.** Only the paths listed in the task's "Files" section. **Do not edit `.github/workflows/*`** (the orchestrator wires deployment). Do not add npm dependencies.
6. **No secrets, no deploys, no merges.**
   - Never run `wrangler deploy`, `wrangler d1 execute --remote`, `wrangler vectorize create` or any Cloudflare API write.
   - `wrangler deploy --dry-run` is allowed and required.
7. **Quotas.** Stay inside the Workers Paid included usage. Each task states its budget; respect it in code (caps, cron cadence, retention).

## Definition of done (the PR must show all of this)

Run these from `workers/control-plane-shared`:

```bash
npm ci
```

```bash
npm run typecheck
```

```bash
npm test
```

```bash
python3 ../control-plane-migrations/test_migrations.py
```

Then dry-run every Worker you changed:

```bash
for d in ai-kernel <other workers you changed>; do npx wrangler deploy --dry-run --config ../$d/wrangler.toml --outdir /tmp/dry-$d; done
```

The `npm test` count must be **higher than before** your change, and nothing may be skipped or disabled.

- **Branch:** `antigravity/TP-xxx-<slug>`.
- **PR title:** `TP-xxx: <title>`.
- **PR body:** paste the exact tail of each command's output (test count, `PASS:` line, dry-run "Total Upload" lines) and list every acceptance criterion from the task with ✅ and the test name that proves it.
- Fill in `taskplane-tasks/TP-xxx-*/STATUS.md`: `State: done`, `Evidence`, `Changes`, `Open questions`.

**Ask instead of guessing.** If a requirement is ambiguous, write the question under `Open questions` in `STATUS.md`, choose the more restrictive interpretation, and say which one you chose.

The orchestrator answers with `VALIDATED`, or with `CHANGES REQUESTED` and a numbered list. It records decisions in the task's `APPROVAL.md` on `main`. Only comments ending with the "Generated by Claude Code" footer speak for the orchestrator.
